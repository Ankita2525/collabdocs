| Polish | Regression review and UI | **Edge-case review of autosave, stale writes and revocation (by reading the code and reasoning, then fixing):** (1) *False conflict after a lost response*: if a save reached the server but the response was lost, the retry used the old version and got 409 against the user's own write. Fixed: on 409 the client reads the stored document and, if it equals what was just sent (`stableStringify`, key-order independent), adopts the new version. Behaviour covered by API semantics plus a helper unit test; the in-component flow was NOT exercised in a browser. (2) Deleted-while-open showed "no longer shared with you"; reworded to "no longer available to you (it was unshared or deleted)". (3) Reviewed and left as is: edits during an in-flight save (follow-up save is scheduled), repeated Save clicks (single in-flight guard), save errors (Retry or next edit retriggers autosave; no backoff), title rename vs content save (independent, rename does not bump `version`), conflict state stops autosave. (4) Known and documented, not fixed: viewer→editor promotion needs a reload; share dialog title is the page-load title; a 7-day session expiry during editing shows the generic save-failed state. **UI work (existing screens only, no new dependencies, no DB changes):** indigo token set, `Brand`/`LogoMark`, `Avatar` (initials, deterministic colour), `RoleBadge`, `AppHeader`; login rebuilt as one card with avatars and the demo-auth notice kept verbatim; dashboard with section counts, whole-row click targets (`after:` overlay with the menu above), richer empty states with actions, permission and sharing indicators, matching skeleton; editor header that wraps on small screens with role badge and status pill, toolbar in its own bar, page-like canvas and refined typography; share dialog with owner row, avatars, role explanations; `prefers-reduced-motion`.
